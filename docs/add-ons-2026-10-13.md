# Add-ons

Owner decision, 13 October 2026 (card c5dc18e1): "Add-on support next". The Mac app already
finds the add-ons in `~/quaked` (Arcane Dimensions, Quoth, Malice, X-Men and Abyss of
Pandemonium) but showed them locked, "add-on support … is not yet shown to work". Each add-on
is unlocked on its own, once it is shown to play: its start map and every level load and run
with no engine or QuakeC error, in the app's own page.

## How an add-on runs

An add-on plays over Quake, as an episode does: Quake's packs are mounted first, then every
one of the add-on's packs in order (`pak0`, `pak1`, …), so its QuakeC (`progs.dat`), maps and
pictures replace Quake's.

- `src/engine/common/game_selection.js`: the add-on is a choice (`OWNED_PACKS`) with an entry in
  `MISSION_PACKS` naming its folders (`games/<Name>`, then `resources/<dir>`) and its switch,
  if any. `GameSelection_FetchMission` gives the source build every pack of the first folder
  with a `pak0`, from `pak0` up to the first missing one, in order, as Quake reads a game
  folder, the catalogue probes it and the app's library (`src-tauri/src/library.rs`) reads it.
- `src/engine/client/menu_levelselect.js`: each playable add-on has a Level Select table (its
  maps' own worldspawn messages, with case, spacing and a trailing full stop tidied; at most 14
  levels to an episode's page, so Malice's twenty missions are two episodes). The running game's table is looked up first, so an add-on that runs with a
  mission pack's switch (Quoth with `-hipnotic`) offers its own maps, not Scourge's, and one
  that runs as standard Quake offers its own, not Quake's. Level names start after the
  game's longest map name (`E1M1QUOTH`), one column for all its episodes, and a name too long
  for the 320-pixel menu is cut at a word. Quake's names stay at x 112; Scourge's, Dimension of
  the Machine's and Abyss's move from 112 to 120, so six-letter map names no longer touch them.
- `src/engine/server/host.js`: on an add-on's or mission pack's first run over the player's
  Quake settings, its own `default.cfg` binds are added (`Host_DefaultBinds`), except for the
  port's own keys (W, A, S, D, Space, F, Mouse 1): Malice's binds A and D to look and swim,
  which would have taken WASD's strafe keys (independent review).
- `src/engine/common/game_catalogue.js`: `ADDONS` lists the add-ons shown to play; one is
  playable when its packs hold `progs.dat` and `maps/start.bsp`. Any other add-on stays locked
  with the old reason.
- The Mac app reads every pack of a game from its library (`src-tauri/src/library.rs`, which
  maps folder names to game ids: Soul of Evil was added there) and `desktop.js` mounts the
  game's base and then the game.

## Loose game files

Quake reads a game folder's packs, then its loose files, before the game it runs on. Add-ons rely
on this: X-Men's QuakeC is a loose `progs.dat`; Malice ships a loose `autoexec.cfg`, Arcane
Dimensions a loose `quake.rc`. Both builds now read an add-on's loose `progs.dat`, `autoexec.cfg`
and `quake.rc` (the source build through `GameSelection_FetchLoose`, which refuses a page or a
file over 64 MB) (`GAME_CATALOGUE_LOOSE_FILES`, `src/engine/common/game_catalogue.js`; the app's
`LOOSE_FILES`, `src-tauri/src/library.rs`), build one pack of them (`COM_BuildPack`,
`src/engine/common/pak.js`) and mount it after Quake's packs and before the add-on's own, so the
order matches Quake's (the app's order: `GameSelection_LibraryOrder`). Only the add-on being run
gets its loose files: a player's own `autoexec.cfg` beside Quake is not part of any game. `config.cfg`
is not read: the port keeps its own settings. A loose file that cannot be read, escapes the
library or is over 64 MB is left out without failing the scan. The catalogue probes these files
too (an exact one-byte ranged answer, so a server answering a missing path with a page does not
count), so an add-on whose QuakeC is loose counts as playable.

## Map data the engine tolerates

X-Men's `x2m4` has an edge 0 naming vertices the map does not have. Edge 0 is a placeholder no
face can name (a face's edge list is signed, so it never uses edge 0), and WinQuake never reads it;
the port refused the whole map at load ("Invalid BSP edge vertex"). Now an edge is refused only
where a face uses it, with the edge and map named (`Mod_LoadFaces`,
`src/engine/render/gl_model_bsp.js`; `tests/bsp2_model_test.js`). The failing run is kept as
evidence (`xmen-before-edge-fix.jsonl`): `x2m1` leads to `x2m4`, so both failed.

## Toward any add-on (owner direction, 13 October 2026)

"Instead of having bespoke rules for each add-on and expansion ... make the engine as
automatically adaptive and resilient as possible so any new add-ons or mods that a player may add
in the future does not need its own integration ... use the expansions and add-ons as an example
case for the strategy." The per-add-on entries above (selection entries, the `ADDONS` list, the
hand-written Level Select tables, the app library's folder names) are what that replaces, step by
step, with the add-ons here as the regression suite:

1. Any folder with packs or game code is a game, named from its folder, played over Quake.
   Done (below).
2. The status bar follows the add-on's own `gfx.wad`: Scourge of Armagon's pictures (Quoth has
   `inv_laser`, `inv_mjolnir`, `sb_wsuit`) mean `-hipnotic`, Dissolution of Eternity's (`r_lava`,
   `r_multirock`) mean `-rogue`; otherwise standard Quake.
3. Level Select is built from the game's own maps: each map's message, maps without a player
   start left out, grouped into an introduction, episodes, deathmatch and other levels, at most 14
   to a page.
4. The large-map protocol is used whenever a map needs it. Done for loading (below); the
   protocol's own entity limit (1024) is next.
5. A found game with QuakeC and a map with a player start is playable; no list.
6. Errors stay contained: malformed data no face uses is ignored, and a map or QuakeC error never
   stops the next map loading (`PR_ResetStack`).

## Any folder is a game (step 1)

- The Mac app's library (`src-tauri/src/library.rs`) lists every top-level folder of the game
  library that holds a `pak0.pak` or a `progs.dat` and that no known game names, as an add-on
  `mod_<folder>` (the folder's name in lower case, other characters as `_`; a clash gets `_2`),
  with its packs and loose game files. Dot folders, folders that cannot be read and folders that
  resolve outside the library are skipped. A source build finds the same folders in the served
  `games/` listing (`tools/serve.py`; `discoverFolders`, `src/engine/common/game_catalogue.js`);
  a site has no listing and runs only the shareware.
- The catalogue keeps them beside the known games (`GameCatalogue_SetDiscovered`,
  `GameCatalogue_AllGames`) and judges every add-on, known or found, by one rule: it plays over
  Quake when it brings maps or QuakeC of its own (a QuakeC-only mod plays Quake's maps); the list
  of add-ons shown to play is gone. An add-on of loose files alone (a `progs.dat`, no packs) is
  found and starts too, in the app and the source build (`GameSelection_FetchMission`). A folder
  with no ASCII letter or digit in its name is `mod_addon`; a folder named as a placeholder
  (Dawn of the Machine) is left to it, in both lists. Folder names are fetched percent-encoded.
- Selection treats any add-on the same way (`missionEntry`, `ownedPacks`,
  `src/engine/common/game_selection.js`): Quake's packs, then its folder's loose files and
  packs; its own saves and settings (`quake_save_<id>_`, `quake_config_<id>`). Malice, Abyss of
  Pandemonium, Soul of Evil and X-Men lost their own entries; only Quoth keeps one, for its
  `-hipnotic` switch, until the status bar follows `gfx.wad` (step 2). A source build that starts
  on a found add-on's address (`?game=mod_...`) lists the library first
  (`GameSelection_NeedsDiscovery`). In the app's download mode a found add-on downloads Quake's
  data packs (its base's).
- Still to come for found add-ons: their own Level Select (step 3; until then Level Select shows
  Quake's), box art (a plain box), and New Game starting from the add-on's own start map when it
  has none named `start`.

## Limits raised for what add-ons need (Quakespasm's values)

- **Command buffer** (`src/engine/common/cmd.js`, `CMD_TEXT_SIZE`): 256 KB, as Quakespasm (1 <<
  18); WinQuake's 8192 bytes could not take Arcane Dimensions' 8530-byte `quake.rc`, which then
  overflowed ("Cbuf_AddText: overflow") and ran nothing. `tests/exec_config_test.js`.
- **Model vertices and triangles** (`MAXALIASVERTS`, `MAXALIASTRIS`,
  `src/engine/render/gl_model_types.js`): 2000 and 4096, as Quakespasm (1024 and 2048 in
  WinQuake); Arcane Dimensions' `mon_dcrossbow.mdl` passed 1024 and stopped the page.
- **The large-map protocol when a map needs it** (`src/engine/server/sv_large_protocol.js`): a
  map that passes a protocol-15 limit while it loads (more than 256 models or sounds, 600
  entities, or an 8192-byte signon) is loaded again from the start with the large-map protocol
  (`SV_SpawnServer`), which then stays for the session; maps that fit keep protocol 15. Nothing
  has gone to a client by then, and a level change's carried spawn parameters are untouched.
  The two settle frames after the spawn functions count as loading (a mod that creates its
  entities on a first think), and so do Newer Game's respawn models and carried power-up sounds.
  A save with more than 600 entities loads on the large-map protocol, as a new session starts on
  15 (`Host_Loadgame_f`). Two effects of the first attempt can show on a retry after a signon
  overflow: seamless travel's teleport effect is skipped, and `localcmd` text queued by the first
  attempt's QuakeC runs twice. `tests/sv_large_protocol_test.js`,
  `tests/sv_large_protocol_native_test.js` (shareware e1m1 with 700 more entities reloads on it and
  runs; e1m1 stays on 15); trial: Arcane Dimensions' start map loaded on it (282 models).
- **Model meshes** (`src/engine/render/gl_mesh.js`, `alias_mesh_format.js`): the command and
  order buffers are sized from `MAXALIASTRIS` (WinQuake's fixed 8192 ints fitted 2048 triangles), so a
  model at the limit is not cut off; a model past it stops with "has too many triangles".
  `tests/alias_mesh_limit_test.js`.

## Fixes the trials needed

- **Level Select** showed Scourge's table under Quoth (independent review): fixed as above.
- **QuakeC stacks after errors.** The first Malice trial's six maps that failed after the 14
  props came back in a rerun with screenshots: the next level's QuakeC stopped with "locals
  stack overflow". Each prop map stopped its QuakeC with an error ("no info_player_start",
  through QuakeC's `error`), and the locals of the functions it abandoned stayed counted: WinQuake
  reset only the call depth, and only on `PR_RunError`. `PR_ResetStack`
  (`src/engine/progs/pr_exec.js`) now empties the call and locals stacks on every program error
  (`PR_HostError`, `PR_RunError`) and when a map starts (`SV_SpawnServer`, which never runs
  inside QuakeC); `tests/pr_stack_reset_test.js`. Rerun: the same 14 props, then `d2`, `ddm7`,
  `ddm5`, `isle` and `test` all load and play.
- **`find` with an empty string** (Quoth's `e1m2quoth`, `plats.qc`): the port stopped with
  "PF_Find: bad search string" because JavaScript treats `''` as false. In WinQuake's C a string
  is never NULL, so an empty search is valid and matches an empty field. `PF_Find` now does the
  same; its missing-string check mirrors C's and cannot fire here (`src/engine/server/pr_cmds.js`;
  `tests/pf_find_test.js`).
