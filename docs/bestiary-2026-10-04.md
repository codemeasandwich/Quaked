## What the player can use

In stock local single-player **Newer Game**, a previously undiscovered living enemy type starts a first-sighting presentation. Gameplay smoothly slows over0.55seconds to a complete pause; the camera focuses the real posed enemy in a randomly selected left or right half. The opposite half fades and ripples in with its bestiary folio. The player can read indefinitely. A fresh key or shoot press dismisses it, the folio fades out, the camera returns over0.45seconds, and gameplay resumes. Held-before-entry input and early transition input cannot automatically close the page. Dismissal is consumed through physical release and cannot become a shot after return.

The main menu now appends **Bestiary**, preserving all existing action indices and their artwork. The book opens with its temporary cover on the right. Left/right arrows turn two-page spreads; touch selects the previous/next half. Escape returns to the main menu. Locked entries show only their title near the top of a plain page, with no illustration or information. The title-only branch never requests undiscovered artwork.

Discoveries are saved as a browser-profile journal, independently of game saves, new games, death and maps. The key is `quaked.bestiary.v1`, containing version1 and known enemy IDs. Reopening/reloading this site merges stored discoveries into the current session; independent tabs are merged before new writes. Unavailable/quota-limited storage keeps this play's discoveries in memory and the book reports that they are session-only. As with ordinary browser local storage, permanence is per browser profile and site origin; clearing site data removes it, and different hosts/ports/devices are separate profiles. There is no account/cloud synchronization claim.

## Reused engine boundaries

`bestiary_state.js` separates the persistent `BestiaryJournal` from `BestiaryEncounter` timing. A discovery is committed when a valid first sighting starts. Cancelling presentation never clears the journal. Fifteen canonical base-game species are mapped by native class name; the ogre marksman shares the Ogre folio. Asset metadata and supplied page text are book content, not instructions or gameplay scripts.

`r_bestiary.js` observes the actual native client aliases after they have been posed for the frame. Admission requires the active paired local loopback, matching current server/client world, single-player headers, signon4, Newer rendering, ordinary game input, living player, and no loading, respawn, manual pause, intermission, weapon radial menu, level handoff, demo or XR. Only living native enemy identities with visible scene-owned models, an on-screen rendered-bounds center, and a clear BSP/moving-brush center sightline can unlock. It does not unlock enemies merely because they are spawned, behind the player or hidden behind the tested level geometry. Camera-portal previews and unsupported remote/custom species do not independently count as local-native discovery.

This is bounded geometric/PVS visibility, not GPU pixel-perfect visibility against every other model, transparent effect or portal. Event-time alias bounds are recomputed because interpolation changes position attributes in place. The selected model's bounds follow its pose during deceleration. Death, map/context loss or a disappearing target cancels presentation safely; an already seen type remains discovered.

The real renderer camera borrows orientation and a symmetric focus FOV to place the rendered bounds center at approximately NDCx−0.5 or+0.5. Player position and both server/client aim values are untouched. Current native eye, roll/punch orientation and base FOV are refreshed before each borrowed view, so the return does not jump to stale camera state. The native culling basis is updated conservatively around that view. Held weapons and the crosshair are hidden during the encounter. The usual `R_SetupGL` restores the normal camera once presentation is idle; no asymmetric projection is introduced into the deferred receiver pipeline.

A temporary neutral-warm portrait point light makes enemies readable in dark rooms. It uses the same light-selection, receiver and physical shadow atlas as ordinary sources; it does not replace textures, mutate native explosion/muzzle slots or change saved settings. Its stable source/receiver reach is prioritized among the existing eight selected sources, marked live for shadow capture, fades with camera progress and is absent after return/cancellation. Normal gameplay lighting is restored when presentation ends.

Host timing multiplies the current game duration by the encounter scale after the existing host timescale, without writing that preference or `sv.paused`. Fully held/returning states skip native physics and seamless crossing work while continuing connection/message/render service. Client/particle/AI time is also stopped by duration0. Presentation uses real time, so pages and camera returns animate while game time is frozen. Existing audio service remains in its normal host path.

Keyboard/mouse/gamepad dismissal goes through native `Key_Event` with a consumed-until-release latch. Gameplay movement/buttons/impulses are suspended; raw mouse and touch-look deltas are drained, including cancellation and the return boundary. Gamepad button edges still work while analog movement/look is suppressed. Touch taps/fire use the same key path with matching touch-release tracking. `r_bestiary_book.js` draws on the existing HiDPI overlay canvas, restoring the caller's transform, alpha and clip, and keeps book presentation separate from simulation/discovery.
