# Fog (13 October 2026)

The owner queued "skyboxes and fog" from the add-ons (card dadcb966). This is the fog half; skyboxes
follow. Arcane Dimensions, the re-release's Dimension of the Past and Dimension of the Machine, and
Scourge of Armagon's re-release use fog, which this port did not draw ("'fog' is not a field" was the
only sign).

## What it does

- **`src/engine/render/r_fog.js`** keeps the fog: a density (0 is none) and a colour. It follows
  Quakespasm and FitzQuake:
  - a map's worldspawn `fog` key ("density red green blue") sets it as the map loads
    (`R_FogNewMap`, from the renderer's `R_NewMap`); a map without one is clear;
  - the `fog` console command changes it, in Quakespasm's forms: one value is the density, two a
    density and a fade time, three the colour, four density and colour, five those and a fade time;
    text counts as 0 (`fog off`), more values print the usage. A fade runs from the fog as it is.
    QuakeC sends it with `stuffcmd`: Arcane Dimensions' fog controller (`globalfog.qc`) sends
    `fog 0.027 0.370 0.360 0.427` on `ad_azad`, which arrives and is applied.
  - the worldspawn key is read as Quakespasm's Fog_ParseWorldspawn reads it: a leading `_` allowed,
    the last `fog` key winning, values filled in order (missing ones keep their defaults), quoted
    values read whole.
  - every surface fades to the fog's colour with its own distance, as exp(-(density / 64 ×
    distance)²) (GL_EXP2 at density / 64, as Quakespasm): Three.js' `FogExp2`, put on the scene for
    each draw (`R_FogApply`, `gl_rmain.js`) in both pictures, so particles, explosions and see-through
    water are fogged at their own distance and the Newer Game bloom is made from the fogged picture.
    The sky is not fogged by its distance: it takes half the fog's colour (Quakespasm's `r_skyfog` 0.5;
    `R_FogSkyMaterial`, on the three sky materials in `gl_rsurf_liquids.js`).
- **Classic picture**: the colour as given (sRGB).
- **Newer Game picture**: the scene pass is in linear light before the picture's exposure, so the
  colour is made linear and divided by the exposure the last frame got (`R_PostLastExposure`, a hook);
  it then goes through that picture's grade like everything else, so it is a little darker and bluer
  than given.
- **Not Quakespasm's**: fog is mixed in linear light where Quakespasm mixes displayed values (a dark
  surface half-fogged comes out a little lighter); teleporter-window views, the title demo's classic
  half and water probes are drawn without fog; there is no `skyfog` worldspawn key or `r_skyfog`
  setting yet (the skybox half of the card).

## Checks

- `tests/fog_test.js`: the worldspawn reading (pairs, `_fog`, last wins, partial values, a `}`
  inside a value, a map without fog clear), every command form and its usage, a fade passing
  through the values between, the scene's fog in both pictures (density / 64; sRGB as given; linear
  over the exposure), the sky's fixed share, and the renderer's calls in place.
- In the app page (WebKit, classic picture): `fog 0.5 1 0 0` on `ad_azad` turns the far corridor red;
  `fog 0.15 1 0 0` on Arcane Dimensions' `start` fades the far walls fully to red while the sky keeps
  its clouds at half red; `fog 0.038 …` (`ad_azad`'s own) lifts the far end's average from (52, 46,
  44) to (55, 51, 51). The map's own load and AD's QuakeC command were both seen arriving.
- Not yet seen: the Newer Game picture's fog in a browser (Newer Game stalls while loading in
  headless WebKit on this machine, with or without this change).
