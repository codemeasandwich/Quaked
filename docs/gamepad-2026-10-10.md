# Game controllers

Card [36]. Quaked plays with a game controller through the browser's Gamepad API. A Bluetooth controller (an Xbox,
PlayStation or Switch Pro controller, or any the operating system pairs) is paired in the **operating system's**
Bluetooth settings, not in the game. The browser then shows it to the page after a button is pressed with the game's tab
focused. There is no in-game pairing step and no Bluetooth permission prompt.

## The buttons

Standard layout (the browser's `mapping === 'standard'`):

| Button | In the game | In a menu |
|---|---|---|
| A / Cross | Jump | Enter |
| B / Circle | Menu (Escape) | Back (Escape) |
| X / Square | Change weapon (the key `/`, `impulse 10`) | the same |
| Y / Triangle | Scores (Tab) | the same |
| LB / L1 | Run (Shift) | the same |
| RB / R1 | Fire (Ctrl) | the same |
| LT / L2 | Jump, past half travel | Enter |
| RT / R2 | Fire, past half travel | the same |
| Back, Start | Menu (Escape) | Back (Escape) |
| D-pad | Arrow keys (move and turn) | Move between items |
| Left stick | Move and sidestep (deadzone 0.15) | |
| Right stick | Turn and look up and down (deadzone 0.12; `gp_look_yaw`, `gp_look_pitch` set the speed) | |

The buttons press the game's own keys, so they follow the key bindings set under Options. X sent `r` before this card,
which Quake leaves unbound; it now changes weapon.

## How it behaves

* **One controller plays at a time.** The one already playing stays while it is connected, even when the browser
  reorders its list. Otherwise the first connected controller with the standard layout is used, else the first
  connected at all. A controller without the standard layout is used as if it had it, and the console says so once
  (`Controller "…" has no standard button layout: its buttons may not match`).
* **Each button releases what it pressed.** A button remembers the key it sent and lets go of that same key, so A
  pressed in the game (jump) and let go in a menu releases jump, not Enter. A key two buttons hold (B, Back and Start
  are all Escape) goes up only when the last of them is let go.
* **Disconnecting releases only the controller's own keys.** When the controller goes away, or another takes over,
  the keys it holds come up. Keys held on the keyboard or the mouse are not touched, so nothing sticks and nothing
  else is cut short. A reconnected controller starts with nothing held.
* **The sticks** only move and look while playing (not in menus, the console, a demo, or while the Bestiary holds the
  input). The deadzone is cut out and the rest rescaled, so movement starts smoothly at its edge.

The code is `IN_GamepadPoll` in `src/in_web.js`, called each frame from `IN_Move`.

## Checks

* `tests/gamepad_test.js` (4), with a stubbed Gamepad API:
  * The menu-switch release, the shared Escape, X changing weapon and Y for scores.
  * Triggers at half travel.
  * A disconnect, and another controller taking over, release only the controller's own keys.
  * The playing controller is kept, a standard one is preferred, and the choice survives a reordered list.
  * The deadzone rescale, and no movement in a menu.
  * Each rule fails when it is removed: releasing a fixed list, recomputing the key, no count, no stickiness.
* Browser, E1M1, with a stubbed controller in the page (the real input path):
  * X changed the shotgun to the super shotgun.
  * The right trigger held for 1.2 s fired three shells.
  * Disconnecting mid-fire stopped the firing.
  * Reconnected, the left stick walked the player forward about 300 units in a second.

## Not tested

No real controller and no real Bluetooth pairing were available: no make of controller or browser is claimed as tried.
Haptics, gyro aiming and in-game rebinding of the controller's buttons are not part of this card.
