# Games layout and the shareware pak's new home (card [34a], 10 Oct 2026)

## What changed

* `games/` has one folder per Quake game and add-on, each with a `README.md` saying what goes there:
  `shareware`, `Quake`, `Scourge of Armagon`, `Dissolution of Eternity`, `Dimension of the Past`,
  `Dimension of the Machine`, `Dawn of the Machine` (a placeholder: not installed) and, because they are installed on
  the owner's machine, the add-ons `Arcane Dimensions`, `Quoth`, `Malice`, `X-Men` and `Abyss of Pandemonium`
  (listed, not assumed to work). `games/README.md` maps each to Quake's own folder name (`id1`, `hipnotic`, `rogue`,
  `dopa`, `mg1`, `ad`, `quoth`, `malice`, `xmen`, `aopfm_v2`).
* The shareware `pak0.pak` (the only game pack in the repository) moved from the root to `games/shareware/pak0.pak`,
  byte for byte (SHA-256 `35a9c55e…a946af`, a Git rename). No copy is left at the root.
* Everything that read it follows: the page (`main.js`), the room server (`server/game_server.js`, from `server/` as
  `../games/shareware/pak0.pak`), the lobby's and the room manager's production default
  (`/opt/three-quake/games/shareware/pak0.pak`), 119 paths in the tests and tools (found by their position in the code,
  so pack names such as `COM_LoadPackFile( 'pak0.pak', … )` are unchanged), the Python tools, the bake corpus
  (`newer/displacement/corpus.json`'s 21 shareware entries, which `tools/prepare_corpus.mjs` passes to the bake tools)
  and the alias-mesh provenance (regenerated by its tool; the bake itself is byte-identical).
* Owned content is not moved here yet: an owned Quake is still read from `resources/id1/pak0.pak`. Detecting what is
  installed in `games/` is [34b], mounting and choosing it [34c], moving the owned packs [34d].

## Older deployments

Both loaders try the old place next: the page fetches `games/shareware/pak0.pak` and, if that fails, `pak0.pak` at the
site's root; the room server tries its `-pak` path and, when that ends in `games/shareware/pak0.pak`, the same root's
`pak0.pak`. Checked: a folder holding only a root `pak0.pak`, with the room server pointed at
`<folder>/games/shareware/pak0.pak`, loads the start map. A deployment that copies the repository as it is gets the new
path; one that keeps its own `pak0.pak` at the root keeps working.

## What Git tracks

`.gitignore` keeps everything in `games/` out of Git except `games/README.md`, each `games/<folder>/README.md` and
`games/shareware/pak0.pak`. A pack you own put in any folder, a second pak in `shareware/`, a stray file in `games/`
or anything in a subfolder is ignored (`tests/games_layout_test.js` checks a list of both kinds with
`git check-ignore`). On a case-insensitive file system Git also matches `readme.md`; that is harmless.

Folder names have spaces (`Scourge of Armagon`); whatever fetches from them ([34b] onwards) must URL-encode them. The
shareware path has neither spaces nor capitals, so it is the same on a case-sensitive host.
