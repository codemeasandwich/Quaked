# Independent minimal Dev texture and HTML gate plan

The owner explicitly authorized texture and HTML checks for Dev and prohibited a full build in this campaign. Keep the current release/CI checks and Prod restriction. Change the existing staged checkpoint implementation rather than add a parallel build pipeline. This is a pre-implementation plan; no gate code was changed by its reviewer.

## Existing contracts and concrete problem

`core.hooksPath` is `.githooks`. Its pre-commit invokes `tools/distribution/precommit.mjs`, whose current lines 33–42 run dependency bootstrap, all distribution contracts, web and desktop builds, Rust tests, LAN bridge/engine tests and universal Mac packaging. Lines 44–48 produce an exact-tree receipt and publish `dist/staged`. No path classifier currently exists. The texture skill workflow line 134 requires the maintained exact-index hook. Bluey onboarding lines 518–525 prohibit silently following a hook exceeding the Dev gate. The latest owner instruction resolves this conflict in favor of texture and HTML checks for this campaign; it does not waive unrelated native/release verification.

`tests/staged_contract_test.mjs` currently checks that staged bytes/deletions are exported while unstaged/untracked data and the index remain untouched, and that subprocesses lose inherited `GIT_*`. The public Prod hook test in `tests/prod_promotion_contract_test.mjs` verifies that direct Prod commits fail before writes. Preserve both contracts. `.github/workflows/distribution.yml` retains full web trials and both Mac qualification legs for Dev/PR and full gated Prod publication. Do not change it or the promotion/pre-push guards.

## Smallest sound implementation

1. Preserve `assertCommitBranch`, Git environment isolation, exact snapshot build, failure retention and successful receipt publication. Freeze HEAD and the staged tree once. Classify their exact diff, with NUL-safe names, against a narrow explicit allowlist of this texture campaign's authoring paths, its texture documentation/evidence/skill and the particular maintained texture tools/tests. Do not broadly permit `src`, `src-tauri`, runtime registries, box/UI assets, arbitrary `tools`, package/lockfiles, hooks or workflows. Check both endpoints of renames and deletions; a rename out of unrelated scope cannot qualify. Reject symlinks, submodules and unmerged index entries. Empty or unrecognized scope must not silently select the texture path.

2. On **Dev**, a wholly admitted texture diff uses the texture/HTML path. Unknown or mixed nontexture staged scope stops with the exact offending paths and a request to isolate the texture checkpoint or obtain separately authorized verification. It must neither silently qualify nor automatically launch a full build during this campaign. Other branch/release behavior keeps the existing full path under its proper authority. Do not use an environment variable that silently chooses a weaker gate for arbitrary staged files.

3. Export the **pinned tree**, not a later index observation. The existing `write-tree` followed by ordinary `checkout-index` can race another writer and label newer exported bytes with an older tree ID. A small private temporary index loaded from the pinned tree and exported with `checkout-index` is sufficient, while preserving/scrubbing the real hook's Git context as today. Scope classification must use that same pinned tree against the frozen base. Retain the real index untouched and reject a changed real index before reporting a commit-bound receipt.

4. In that isolated snapshot, run meaningful existing Python texture fixture/public-interface suites for the tools being checkpointed (the skill currently names the prepare-master, tier, batch-preview, ordinary-boundary, layered-master, layered-boundary and motif suites). Use the verified Python codec environment, `PYTHONDONTWRITEBYTECODE=1`, and fail if a required suite is skipped or errors. Run a maintained catalog/source/custody closure check over **snapshot bytes**: active master inputs, native Low, catalog/queue/counts, receipt/map seals, proof seals and current touched-producer qualification. Existing receipts contain canonical absolute repository paths: remap only the known repository prefix to the snapshot for reads, preserving original metadata bytes and hashes. Never fall back to unstaged working-tree assets or rewrite sealed receipts to make a check pass. Do not claim that a current receipt alone is an independently repeated artwork/native/CLI qualification.

5. Reuse `npm ci --ignore-scripts`, the existing distribution contract command, `npm run build:web`, and `node tools/distribution/verify-site.mjs dist/web` in the snapshot. Node's distribution contracts use fixtures and protect packaging/Prod/staged invariants; they are distinct from the Rust/LAN/native build suite. These steps are a concrete minimum HTML check using the existing build, not a new placeholder. Do not run `build:desktop`, Cargo, engine/LAN execution, Tauri or universal Mac packaging on this path. Keep builds in the existing snapshot; preserve the current user HTML until a successful replacement is ready. An HTML artifact does not integrate this authoring-only catalog into runtime packs.

6. The receipt must identify base commit, staged tree, scope (`Dev texture and HTML`), exact command outcomes, tool/environment identity and HTML output digest. Record `macBuilt:false` and the explicit deferred native/release boundary; never reuse the older `macBuilt:true` wording. Keep full local release support separately reachable only with explicit full-scope authority, and leave full CI/release/promotion requirements intact. New local HTML qualification is not remote CI success.

## Gate bootstrap and independent tests

Changes to the classifier/hook itself and its tests must **not** become a permanent texture-scope exception. The initial bootstrap needs an independent review of exact gate source/test bytes, bound to the frozen base and narrowly listed gate-control paths. Admit those exact blob hashes only for this explicitly authorized bootstrap, and apply the normal texture classifier to every other staged path. A new/changed unreviewed control file, package/lockfile, native file or foreign asset still stops. Do not create a generic “skip full build” switch or a path-prefix exception for all distribution machinery. If the bootstrap cannot be constrained this way, stop for the coordinator rather than relax classification.

Extend the existing staged contract file using disposable repositories and injected command recording, so tests themselves create no app/native builds. Prove: texture-only Dev chooses exact expected texture/HTML commands; unknown/mixed/native/box/UI/package/CI changes fail before commands; rename/deletion endpoints and symlink/submodule/conflict cases reject correctly; unstaged/private data cannot affect classification or outputs; a concurrent real-index update cannot change the pinned export or earn a misleading receipt; bootstrap byte/hash mismatch is rejected; command failure prevents successful publication; the successful receipt truthfully says no Mac build. Preserve the public direct-Prod rejection and the full branch's existing command list. Keep dedicated release/CI contracts unchanged and run their lightweight fixture checks as appropriate.

The coordinator implements the narrow change, then obtains independent code/fixture review and runs the actual exact-index texture/HTML gate. This plan grants no Git, native-build, release or provider authority. Full release/CI gates remain required at their existing boundaries.

Root's independent implementation review additionally required dedicated exclusive output custody: Dev texture publication uses `dist/texture-checkpoints/<pinned-tree>/`, never deletes or reuses an existing destination, and preserves foreign `dist/staged` output. The corrected implementation and its new preservation/cleanup fixtures are documented in IMPLEMENTATION.md. Full-mode publication is unchanged.
