## Correct target and native geometry consequences

Fresh target-name checks find no rtex018 entry in runtime `textures`, `glass` or `ordinaryVariants`, and no rtex018 name or exact native-identity row in the current offline 67 catalog. Native source provenance is `docs/hexen2/textures/parallel-2026-10-20/stream-18-rtex018/native-proof.json`; this document does not qualify the held artwork or authorize a new scene source.

Helper 01's sealed `window-instance-audit/evidence.json` and `summary.json` under that stream report 206 target faces in cath and 12 in demo1. Every recorded face belongs to an inline `breakable_brush` entity; none belongs to world model 0. There are 21 such model references in cath and two in demo1, which are compiled brush assemblies, not a confirmed count of windows. Cath has 164 faces intersecting multiple positive-area UV cells and 42 partial single-cell faces; all 12 demo1 faces intersect multiple cells. No individual face covers exactly one complete cell. Cath has 20 complete group cells requiring multiple face pieces; demo1 has none. These are geometry facts, not 218 windows or 654 independent scene placements. Front, back and edge surfaces can represent the same assembly, and UV cells do not prove opening boundaries. Face-fragment grouping and actual material/opening semantics remain to be reviewed.

The actual retained native primary reference `/private/tmp/quaked-hexen2-reference-20261018/uhexen2/common/bspfile.h:25,82` declares `MAX_MAP_HULLS 8` and `dmodel_t` with nine 32-bit floats plus eleven 32-bit integers: an 80-byte native record, headnodes at 36–64 and visleafs/firstface/numfaces at 68/72/76. Its exact local bytes are hashed in the v2 witness; no new upstream retrieval or reference-revision claim is made. The current JavaScript `src/engine/common/bspfile.js:16` has four hulls, and `src/engine/render/gl_model_bsp.js:89,1140` uses 64-byte records with fields at 52/56/60. `gl_model_types.js` sizes model hull arrays from the same four-hull constant.

Independent reads of the actual PAK members rechecked both archive and BSP hashes against helper 01's sealed evidence and validated all native 80-byte face ranges. Cath's model lump is 7,440 bytes: 93 native records, remainder 16 under the current 64-byte loader, which will reject that lump. Demo1's lump is 8,000 bytes: 100 native records but also divisible by 64, so divisibility alone can permit an incorrect parse. This is a BSP model/world-load prerequisite as well as an inline-brush rendering prerequisite; an art replacement or generic BSP29 version match does not establish compatibility. No current loader was executed or changed for this diagnosis.

For the target, the existing brush renderer is the immediate draw-path reuse candidate: `src/engine/render/gl_rsurf_brush.js:175` groups each inline model's surfaces by base texture and lightmap and merges their polygons. Per-window fragments must enter that path while retaining entity transforms, original lightmap coordinates and face ownership. Breakage/removal must remove all of the assembly's fragments together through the existing entity lifecycle; scene choices cannot survive as detached world meshes. Opposite faces/edge pieces need a reviewed relationship to the same opening rather than independent randomization. Do not defer the brush path behind a world-only implementation and call rtex018 complete.

## Existing path worth reusing

`Mod_LoadFaces` ends with `Mod_CrateVariants` (`src/engine/render/gl_model_bsp.js:698`). This runs during brush-model loading, gated by Newer Game, `r_newer_textures`, and the crate control. The installed hooks come from `src/newer/install.js:52,162` through `src/engine/common/hooks.js:274,779,901`.

The crate loader measures surface geometry and actual texinfo UV extents, asks the pure `R_CratePlan` for choices, creates a small set of texture clones, and copies texinfo per selected surface. It keeps original indexed pixels, dimensions and mip offsets, sets `classicBase` to the original GL texture, calls the normal texture upgrade function, appends clones to the model texture list, and changes the surface's texinfo reference. `GL_LoadTexture` registers the new textures on the loading model for existing disposal. This is the appropriate lifecycle and ownership pattern to reuse.

Do not copy the crate identity algorithm. `R_CratePlan` groups touching AABBs and identifies 64-unit crates. Its random seed is chosen once per page and mixed with map/corner, so revisits retain the same choice. The requested window policy needs a fresh level-load assignment, stable throughout that load. `Host_ClearMemory` calls `Mod_ClearAll`, which disposes brush-model textures and marks models for reload. `Mod_LoadModel` can also return already-loaded models; previews and other-level loads exist. Choose the level generation once at the actual committed level-load boundary, then pass it to planning. A preview, prewarm, repeated frame or asynchronous completion must not consume a new gameplay level seed. Reuse assignments for other views of that same loaded level; decide save/reload expectations explicitly before implementation.

`R_NewerTextureUpgrade` (`src/newer/render/r_newertextures.js:223`) already selects glass by texture name plus `R_GlassTextureKey`, reconstructed from native RGBA including the original fullbright contribution. A known glass name with unmatched native identity terminates at native fallback; ordinary variants and base-name art must not bypass it. Ordinary variants bind their own diffuse and relief. Extend this exact-native selection with a scene choice within a matching window entry, rather than inventing synthetic unguarded names or replacing one shared source texture for all windows.

The existing asset route is logical `newer/textures/` through `COM_NewerJSON`, `COM_NewerURL`, distribution availability, and `assets/layout.json`'s `newer/` → `assets/game/` mapping. Continue that route. The loader currently selects one `file` and associated height/normal/gloss/opening roles; it has no Mid/High selector. Adding a bounded tier binding is real work, not an existing capability. Preserve legacy manifest entries and fail closed for invalid explicit native/scene/tier entries.

## Smallest sound window assignment

Use one exact-native window entry with three reviewed scene bundles by default, retaining the same frame, palette, opening and physical interpretation. Each scene has one final adequate RGB/full-float master feeding its own direct Mid 4× and High 8× maps; Low is always the original. No separate tier generation and no unrelated scene/relief combinations. Glass, alpha, emission and opening semantics require their own qualification; the ordinary opaque tier CLI alone does not establish them. Artist scenes remain future work pending exact plans and issuance authority.

Define an instance by native identity, brush/submodel identity, coplanar world placement and continuous native UV chart/tile phase. Disconnected windows with coincident UVs must remain distinct. Faces covering the same physical window must share one instance and one random scene. Avoid face index, AABB contact alone, rounded world position alone, or texture name alone as identity. Mirrored, rotated, scaled and negative UVs, non-axis-aligned faces, partial edge tiles and exact tile boundaries need explicit handling. Actual native artwork must establish whether one repeated tile represents one window or several openings; helper 01's census proves the one-face/one-window assumption unsafe; an actual semantic opening grouping is still required before fixing that rule.

Current opaque geometry (`BuildSurfaceDisplayList`, `src/engine/render/gl_rsurf_lightmaps.js:518`) creates one polygon per BSP face with native texture-tile UVs and independent lightmap UVs. World batching (`src/engine/render/gl_rsurf_batches.js:419`) picks one texinfo texture per surface and groups by texture/lightmap. Consequently, texture cloning per face cannot assign different scenes to multiple windows on one face. Conversely, independent random choices per face would split a window spanning faces.

Reuse the existing model and batch renderer. For a whole one-window surface, the crate clone/texinfo pattern suffices. Where the census proves multiple windows per face, the smallest sound extension is render-derived polygon fragments clipped at the measured window-cell boundaries in native UV space. Each fragment keeps interpolated position and lightmap UVs, original face ownership, normal, visibility leaves and lighting; it carries a selected cloned texture. Feed these fragments into the existing texture/lightmap batches and brush path. Do not split BSP collision, alter the on-disk map, allocate fake model slots, or introduce a second renderer. The same fragment rule must cover every consumer required by actual maps, including inline brushes and other-level views. This is a proposal requiring geometry review, not a claim that existing `poly.next` consumers already support multiple textures.

For supported windows, pick one of the three entries uniformly using a level-generation seed and a stable instance key. Repeated choices are allowed; random assignment does not promise three different adjacent windows. Share GPU clones only when native source, selected scene, tier and UV transform agree. Do not mutate the base texture shared by other instances. Unsupported or ambiguous instances retain their unchanged native picture with a visible diagnostic; silently skipping those instances cannot count as complete per-window delivery.

## Classic, tier and cache preservation

`R_ClassicTexture` follows `classicBase` before creating a native twin. Preserve this so Classic and split comparison use the original native pixels and original UV phase. Geometry fragments may partition a native face but must reconstruct its identical coverage and UVs. A graphics toggle must not reroll scenes. Reverting enhanced textures must not lose the stored level assignment.

The picture/scalar promise caches are keyed by asset file, and the manifest is loaded once per module. Use immutable distinct role filenames and the existing manifest version convention; do not reuse one filename for another scene or tier. Variant selection must be captured before asynchronous loading. Prevent an old level/tier completion from installing stale maps on a current or disposed clone. Missing roles must follow the existing matte/native fallback and readiness behavior, never borrowing another scene's height or gloss. Make malformed complete-bundle handling explicit so partial scene changes cannot pass as a qualified result.

`NormalInputKey` in `src/newer/assets/normal_prepare.js:75` already hashes generator version, dimensions, settings and all diffuse/fullbright/scalar/authored-normal/edge bytes. Reuse this cache, cancellation on disposal, and readiness path; no new scene cache or normal generator is needed. Scene identity belongs in selection/provenance, while identical physical inputs can safely share content-addressed prepared data. Preserve the existing `newertextureupdated` notification and normal invalidation when image data changes. Keep all selected clones on model-owned texture/readiness/disposal lists.
