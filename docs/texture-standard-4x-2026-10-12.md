# The 4x art standard

Owner ruling, 12 October 2026: "resize the images skins and textures to the 4X so that
then becomes the standard and we have the normal maps match and then we've only got one
version". Shipped Newer textures and skins are at most 4x their original Quake size, in
the source tree itself: the web build and the Mac app use the same files, and the shipped
normal maps are baked from them. The owner chose to apply it to every asset above 4x, in
batches (shareware, then the full game, Hipnotic and Rogue), each tested, committed and
pushed.

## What was above 4x

Scanned against the original id1, Hipnotic and Rogue PAKs (each texture or skin compared
with every native size of that name): 6 world textures (`tech04_3`, `tech07_2`,
`tech08_1`, `tech09_3`, `tech10_3`, `tech11_2`, all 6x) and 46 custom enemy skins at 5x to
8x. Everything else was already at or below 4x.

## Method

Each asset is regenerated by the generator that made it where one still reproduces the
committed file (pixel for pixel); otherwise the finished file is resampled.

- **Re-fit at factor 4.** Skins from the generated-skin importer
  (`tools/texture_sheets/fit_generated_skin.py` with its recipe in
  `tools/texture_sheets/sources/generated-2026-10-12/`) are re-fitted with the recipe's
  `factor` set to 4. Before changing anything, the factor-6 run was checked to reproduce the
  committed diffuse and height byte for byte (system Python 3.9.6, Pillow 10.1.0, NumPy
  1.26.2, SciPy 1.11.4, as the skin docs record). The recipe now says 4, so a later re-fit
  keeps the standard.
- **Re-author heights.** Custom enemy heights made by the height author
  (`update_enemy_heights.py` `height_for`, `enemy_height_authoring.author_height`, the
  generator `tests/verify_enemy_heights.py` checks) are re-authored from the 4x diffuse. The
  Shambler's reviewed annotations are in `reference_size` coordinates, so they carry over;
  its recipe's `diffuse_rgb_sha256` guard now names the 4x diffuse.
- **Resample.** Where no generator reproduces the file (an upscaler that cannot be re-run;
  `tools/craft_normals.py`, whose texture profiles have since changed and would alter relief
  strength; or a registration-based fitting tool whose alignment search would run afresh at
  a new scale), `tools/texture_sheets/standardise_4x.py` resamples the finished file with
  Lanczos to exactly 4x the native size, keeping its format: lossless stays lossless, lossy
  WebP is re-encoded at quality 95, alpha is kept. The six crafted `tech` heights were lossy
  WebP as `craft_normals.py` wrote them, so they stay lossy (an exception to keeping height
  maps lossless). The tool writes every file beside its original and renames them all only
  after all succeed, and refuses to re-run a plan that already records results. Its plan
  files under `tools/texture_sheets/sources/standard-4x/` record each file's target and
  before/after size and SHA-256; `tests/texture_seams_test.py` and
  `tests/verify_head_skins.py` accept a resampled file only when it is exactly that record.
- **Normals.** `tools/bake_normals.mjs` re-bakes every level that uses a changed texture
  (found by scanning the BSP texture lists in every PAK and loose map) and every changed
  custom skin, in the namespace and PAK it was first baked with. Samples that this batch
  left unreferenced are removed (a few other unreferenced samples are kept on purpose:
  `tools/distribution/manifest.mjs`); `src/newer/assets/normal_bakes.js`, the startup
  prefetch list and the normals snapshot in `docs/distribution-local-only.json` are
  regenerated, and `tools/check_distribution_policy.py` passes.
- **Caches.** `newer/enemies/index.json` and `newer/textures/index.json` versions are bumped
  so browsers fetch the new files.

A height map 1.5x smaller gives steeper per-pixel slopes at the same `heightStrength`, so
relief on a resampled skin can read slightly stronger; side-by-side checks at display size
showed no visible difference for the batch-1 texture, dog and shambler.

## Batch 1: shareware (done)

- Re-fitted at 4x: `dog/custom` (1872x1014 to 1248x676; PNG 1.48 MB to 760 KB).
- Re-authored at 4x: `shambler`, `zombie` and `demon` heights, from their resampled diffuse.
- Resampled: the six `tech` textures and their crafted heights (6x to 4x); `backpack`,
  `suit` and the three `armor` skins; `shambler`, `zombie` and `demon` diffuse (5x to 4x).
- Re-baked: 22 levels using the `tech` textures (shareware `start`, `e1m1`; id1 `base32b`,
  `dm3`, `e1m1`, `e2m1`, `e3m1`, `e4m1`, `start`; Hipnotic `hip1m1`, `hip1m3`, `hip1m4`,
  `hip1m5`, `hipend`, `start`; Dimension of the Past `e5m1`, `e5m2`, `e5start`, `start`;
  Dimension of the Machine `mge5m1`; the Newer hub `start`; the loose `rapture1`) and the four
  custom skins with heights. 10 samples replace 10; 3 stale `mge5m1` samples were also
  removed (that map's BSP and native keys are unchanged; six of its textures are no longer
  upgraded by the current engine, so its old manifest entry was already out of date). The
  manifest holds 1953 samples.
- Startup prefetch: `tools/build_startup_normal_prefetch.mjs` now resolves a variant's bound
  model (`nativeModelSha256`) against the shareware PAK for both campaigns, so a variant bound
  to another game's model (such as the Rogue Ogre's) is never added to the hints; the
  regenerated `e1m3` hints also replace a stale Ogre key with the current one.
- Web build: normals data 211 to 197 MB, site 610 to 594 MB; the http trial passes.
- Tests: the dog test now expects fourfold dimensions; the fish and Rogue Ogre tests' pins of
  the accepted dog files and normal key follow the new files. Failing before this work and
  unchanged by it: the Enforcer and Old One tests (they freeze every other skin's manifest
  entry, which later accepted work changed), `height_shadows`, `texture_seams_test.py`
  (a missing `demon-face` base file and a later catalogue entry), `verify_head_skins.py`
  (the soldier height) and the Centroid source check (an untracked source image no longer on
  disk). `newer/displacement/manifest.json` records the texture index's earlier hash for its
  manual audit only; nothing reads it at run time.

## Batch 2: full game (done)

- Re-fitted at 4x: `fish/custom` (recipe `fish-v2.json` factor 6 to 4: 1560x1164 to 1040x776;
  the factor-6 run reproduced the committed files byte for byte first).
- Re-fitted at 4x: `shalrath` and `oldone`. `fit_vore.py` and `fit_oldone.py` use fixed part
  mappings (no alignment search); their factor and bleed are now named constants,
  `FACTOR, BLEED = 4, 8` (the same two native texels the factor-5 fit bled).
- Resampled from the accepted fit (5x to 4x), heights re-authored from the 4x diffuse:
  `enforcer`, `tarbaby` and `hknight`. `fit_enforcer.py`, `fit_tarbaby.py` and
  `fit_registered.py` were each checked to reproduce the committed pixels first; they search
  for part alignment in canvas pixels at factor 5, so re-running them at 4 could shift
  accepted art, while resampling keeps it. `SOURCE.json` gives the shipped `factor`,
  `dimensions` and `files`; the fit's own are under `standard4x` (`fitFactor`,
  `fitDimensions`, `fitFiles`), and its fit-unit fields (bleed, parts, statistics) say so.
  Their docs' Reproduce steps now fit into a scratch directory and then resample. Record:
  `tools/texture_sheets/sources/standard-4x/batch2-id1.json`;
  `tests/standard_4x_records_contract_test.mjs` checks that each `SOURCE.json` agrees with it.
- `tarbaby/rogue0` and `hknight/rogue0` are byte copies of the base custom skins (the Rogue
  tests require exact compatibility), so they follow them; their `SOURCE.json` reuse chain
  is updated.
- Re-baked: the eight custom variants (in the `id1` namespace; the `rogue0` copies with
  the Rogue PAK alone, since a later PAK on the command line wins). 6 samples replace 6 (the
  copies share their base's inputs); 1953 samples. Skin cache version 48.
- Tests: the identity tests expect fourfold dimensions and the new digests. The Enforcer and
  Old One tests still stop at their pre-existing cache-revision pin.

## Batch 3: Hipnotic (done)

- Re-fitted at 4x through their recipes (`tools/texture_sheets/sources/generated-2026-10-12/`):
  `armabody` (factor 7, 1512x1358 to 864x776) and `grem` (factor 6, 1848x1014 to 1232x676).
  Both factor-6/7 runs reproduced the committed images first (the gremlin's `SOURCE.json`
  gains the importer's newer `atlasBox` and `registration` fields).
- Armagon's flames: `fit_rogue_skins.flatten_height` pads the flat flame region by six
  pixels. At factor 4 the fitter's polygon rasterizer and the test's per-texel-centre
  rasterizer differ by a pixel at triangle edges, so 285 test-padded pixels were left below
  maximum height. Enlarged maps (factor above 1) now pad seven pixels (recorded as `padding`
  in `SOURCE.json`); the fitter still
  refuses padding that reaches another UV surface, and the native (factor 1) map keeps six,
  so its height file and normals are unchanged.
- Resampled from the accepted fit: `armalegs` (its recipe's registration box
  `[0,4,1368,1210]` is in factor-6 pixels and has no whole-pixel factor-4 equivalent, so
  re-fitting would change the accepted registration; changing only the factor misplaces the
  source and leaves a UV component uncovered; 1368x1164 to 912x776) and `scor` (its source image is untracked and no longer on disk; 1540x780 to
  1232x624). Heights re-authored; `SOURCE.json` as in batch 2; their docs' Reproduce steps fit
  into a scratch directory and then resample. Record:
  `tools/texture_sheets/sources/standard-4x/batch3-hipnotic.json`.
- Re-baked the four custom variants in the `hipnotic` namespace with its PAK; 4 samples replace
  4; skin cache version 49.
- Tests: the Armagon test's recipe factors and flame-mask factor are 4; the Gremlin and
  Centroid tests expect fourfold dimensions. The Centroid source check still fails as before
  (its untracked source image).

## Batch 4: Rogue (done)

- Re-fitted at 4x through their recipes (each first reproduced its committed images byte
  for byte at its old factor): the dragon, Overlord and mummy (built-in recipes in
  `fit_rogue_skins.py`), `lavaman`, `sword`, the six `eel2` skins (base first; the charge
  skins are built from it and still differ only inside the electrical masks), the nine
  Guardian skins (the three stone skins share one input), `knight/rogue1`,
  `tarbaby/rogue1` and `rogue2` and `hknight/rogue1`.
- Resampled from the accepted fit: `wrath` (its registration box `[0,0,1488,1180]` is in
  factor-6 pixels with no whole-pixel factor-4 equivalent; 1488x1164 to 992x776), height
  re-authored. Record: `tools/texture_sheets/sources/standard-4x/batch4-rogue.json`.
- Re-baked the 25 variants in the `rogue` namespace; 23 samples replace 23; 1953 samples;
  skin cache version 50.
- Tests: identity tests expect fourfold sizes; checks that sampled the fit at a fixed
  factor (Wrath's hood and eye windows, Lava Man's pigment points, the eel's charge
  envelope, the knight statue's covered-surface floor) now use factor 4 and still pass.

After this batch no texture or skin with a Quake original is above 4x (re-scanned against
every PAK in the library). 66 textures have no original (Newer-only art such as crate
variants and the hub logo), so the standard does not apply to them.
