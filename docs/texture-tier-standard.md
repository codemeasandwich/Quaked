# Shared Quake and Hexen texture standard

Owner instruction, 19 October 2026: this standard applies to Quake, its official expansions, Hexen II and Portal of Praevus going forward.

**Quake amendment, 20 October 2026:** the [current Quake mission](quake/textures/MISSION.md) retains lossy WebP Q92/method 6 for colour and requires lossless WebP/method 6 for height, normal and mask maps. This supersedes the earlier all-lossy rule for the Quake lane. The separate Hexen campaign and sealed historical evidence retain their recorded scope. Quake's additive `derive_quake_texture_tiers.py` implements and verifies per-role exports while leaving the legacy producer unchanged. Existing all-lossy exports become compliant only after actual direct-master regeneration and verification; codec compliance never clears a separate artwork HOLD.

| Tier | Dimensions relative to native | Source |
|---|---|---|
| Low | 1× width and height | Unchanged original game texture |
| Mid (default) | 4× width and height | Direct reduction of the one retained master |
| High | 8× width and height | Direct reduction of the same retained master |

The primary quality gate is recognisable real-world material. At close range and in both enhanced tiers, the texture must visibly read as a plausible physical material with coherent natural structure and finish. Resolution, sharpness, discernible marks and low distance error are insufficient. If the native material is ambiguous, document a concrete plausible interpretation for review; do not deliver abstract high-resolution mottling or synthetic grain under a neutral label. Preserve original colour, style, intended forms and feature scale while adding appropriate material detail.

Generate one shared photographic source per distinct native texture content, at least 8× native width and height. Owner clarification, 21 October 2026: GPT image-editing revisions of that source are allowed; retain one final master feeding both tiers. Preserve the original, exact prompts, issued revision records, parent and returned-file hashes, actual model-call totals and rejected attempts. A revision is not a separately authored tier. Select one qualified final source, complete colour/layout/edge registration at master resolution and retain one active RGB/relief master package. Requalify RGB, relief and both tiers after a source edit. The [tracked-edit contract](../skills/quaked-texture-authoring/references/source-edits.md) defines custody and final-source selection. Never generate or author Mid and High independently. Do not infer a native alias from a matching texture name alone. Exact-content aliases may reference the same retained master package and tier files only after checking native dimensions, palette, indexed pixels, every original mip level, provenance and material semantics. Preserve each native identity and Low binding, record the proof, and distinguish physical file counts from native map bindings; never generate a redundant master for verified identical content.

Author scalar relief once at master resolution, with full-precision height values. Derive each tier's height directly from that scalar master and correctly scaled normals from that uncompressed reduced height. Height amplitude is shared; normal slopes account for texel density. Do not derive a tier or its normals from an already compressed tier map. Masters remain lossless authoring data. Under the revised Quake mission, colour exports use lossy WebP quality 92/method 6; height, normal XYZ and masks use lossless WebP/method 6. The original 19 October export contract used lossy Q92/method 6 for all enhanced roles and remains the declared contract of historical receipts and the separate Hexen work until its owner adopts an amendment.

Owner extension, 21 October 2026: the current Hexen II stained-glass window may have multiple artist-scene variants, with selection once per physical window on level load. Each named variant retains one final RGB/relief master feeding BOTH Mid and High; all variants retain the same native Low, frame, feature scale and representative distant palette. Qualify each variant independently against that original. A common relief field is valid only when unchanged frame/glass geometry and flat painted-colour semantics are proved. Separate art-variant counts from native coverage and actual physical files; never count multiple paintings as multiple completed native identities. Three variants is the coordinator's first-increment choice, not an owner limit or a rule for all textures. Runtime selection and actual Hexen integration require their own verification; the asset standard alone does not implement them.

Use a Python 3 environment with Pillow and NumPy installed (the current verified authoring environment is `/usr/bin/python3`). The shared offline CLI is `tools/texture_sheets/derive_texture_tiers.py`:

```sh
/usr/bin/python3 tools/texture_sheets/derive_texture_tiers.py \
  --original original.png --master master-color.png \
  --height-master master-height.npy --output NEW_OUTPUT_DIRECTORY
```

It requires unchanged native input, lossless RGB PNG master of matching aspect and at least 8× dimensions, and a matching finite float32/float64 height array in [0,1]. It refuses existing destinations, too-small masters, malformed scalar sources and invalid strengths. It does not generate art, author height, register resources, change runtime settings or alter Low. Output manifests declare Mid as default for future integration; existing game settings are not silently rewritten by an authoring tool. This example documents the current legacy all-lossy implementation; it does not yet satisfy the revised Quake data-map codec requirement. Use the qualified additive Quake CLI described below for that requirement; never obtain a new lossless data map by transcoding an old lossy output.

Both enhanced tiers require comparisons against the original at half and quarter original dimensions, using the same BOX reduction on both inputs. Record decoded measurements but review actual colour/style/intention, forms and feature scale visually. Check repeated tiles and relief under opposed lights at both resolutions. Preserve source edge alignment and intended material joints; reject new perimeter bevels/shading, missing little bricks, pixel contours and artificial grain. Record decoded height/normal compression divergence rather than assuming exact equality.

For the revised Quake mission, use the same derivation arguments with `tools/texture_sheets/derive_quake_texture_tiers.py`. It reuses the existing periodic colour reduction, float scalar reduction and UV-scaled normal mathematics. Diffuse uses the legacy Q92 encoder; explicit height/XYZ roles use lossless WebP and require exact decoded channel equality. The manifest records eight-bit rounding separately from integer compression error, so lossless export does not claim lossless float quantization. Current opaque native references may be RGB or fully opaque RGBA; transparency requires its own qualified authoring path. Use `build_quake_texture_batch_review.py` with a schema-3 batch and bound schema-2 tier receipts. Existing source-hash-bound producers and historical review HTML stay unchanged.

A visually confirmed top/bottom discontinuity in an unqualified opaque material can be corrected before final relief authoring with `tools/texture_sheets/register_texture_boundary.py`. This opt-in command validates and replays the retained original/source/prompt package, subtracts a zero-mean periodic Poisson boundary field from the lossless registered RGB, and authors the final scalar height once. It never moves features or consumes tier maps. Its new package keeps the same single generated source; pass that package's RGB and float height directly to the existing tier CLI. This is not automatic tiling acceptance: review both axes, corners, local clipping, distance similarity and decoded relief for both tiers. Retain prior failed receipts and registration recipes when retiring superseded unqualified binaries.

For a facing above exposed substrate, use `tools/texture_sheets/prepare_layered_texture_master.py --recipe SOURCE_BOUND_JSON --output NEW_DIRECTORY`. It reuses the established layered-veneer masks, wrapped blur and ordered material planes, keeping RGB unchanged. Full-precision photographic detail is composed into the explicit planes at master resolution, with one final float32 cast. The recipe pins native identity, the verified original master, native/RGB hashes, structural regions and clipping-safe plane values. `bevelPixels` retains its old 256-reference meaning: a value of 1.5 at a 1024px square master gives a six-master-pixel interface. This affects intended material interfaces, never the image perimeter. Derive both tiers with the shared tier CLI. Plane bounds establish facing above substrate; actual mortar-versus-brick samples and both-tier lighting still require separate review. The portable interface regression is `tests/texture_layered_master_test.py`.

The first application is the Hexen authoring increment in `docs/hexen2/textures/TWO-TIER.md`. Existing Quake deliveries and historical receipts are preserved; new Quake assets use this common standard. Retrofitting older assets requires their retained adequate-resolution source, never upscaling or transcoding the compressed 4× counterpart. Runtime/pack binding and owner acceptance remain independently verified steps.

The current derivation CLI covers opaque RGB surfaces with scalar relief and separate XYZ normals. Alpha/glass masks, emission, liquid, sky and animation families require their own reviewed source semantics; this tool does not qualify them by merely resizing them. Their future enhanced tiers must obey the same common master 4×/8× contract and the active campaign's per-role encoding policy.

For a missing flat colour motif inside otherwise accepted photographic geometry, `tools/texture_sheets/prepare_motif_texture_master.py --recipe SOURCE_BOUND_JSON --output NEW_DIRECTORY` reuses the full-native periodic colour-field policy and bounded smooth compositor. The guide is restricted to reviewed interior rectangles with four multiplied inward smoothstep ramps. All canonical RGB outside those supports, including the image perimeter, remains byte-identical. The verified initial float height is replayed unchanged so pigment markings do not become invented embossing. This is a local source-guided colour repair, not global pixel reconstruction, spatial resampling, another generation or separate tier authoring. Derive both tiers normally; expect their eight height/XYZ files to remain identical. Lossy diffuse encoding can spread changes beyond the canonical support, so actual encoded replay and focused half/quarter, detail, repeat and relief reviews remain mandatory. The portable interface regression is `tests/texture_motif_master_test.py`; retain failed source/guard receipts when a successor is qualified.
