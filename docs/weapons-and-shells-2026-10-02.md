## Architecture and contracts

`tools/import_weapons.py` reads only the supplied assets and original game data. Full glTF node matrices are baked before orientation and scaling. It imports only the shotgun-shell primitive from Weapon Pack. Runtime geometry retains donor triangles, UVs and copied textures; generated JSON carries poses for the existing alias renderer, avoiding a second runtime model loader. `newer/weapons/index.json` records every independently fitted role, body/barrel anchors, scale/offset, optional held offset, source axes, source hashes, material/style factors and excluded native vertices.

`src/newer/render/r_weapons.js` uses existing `COM_NewerJSON` / `COM_NewerURL`, so loose assets and the existing `newer.pak` packaging path work. Shared textures are loaded once per donor. Until a role's geometry and all textures are loaded, it retains native geometry/material. Failed assets retain native fallback and expose diagnostics through `R_WeaponStatus()`. Original MDL identity remains authoritative for weapon selection, culling, pickup behavior and animation frame timing.

`gl_mesh.R_DrawAliasModel` selects an optional imported pose template at its existing geometry boundary. Existing transforms, lighting samples, bob, pitch/yaw/roll, invisibility/death/chase visibility, viewmodel depth range, and XR placement remain in their native paths. The axe uses original native pose templates with fitted donor UVs and the original hand subset with original UVs/skin. Native and imported templates can switch in either direction without stale geometry/colour buffers. `r_classicstate` restores the extra template/colour-buffer bookkeeping after the comparison pass.

Imported alias materials reuse the existing custom-skin normal/albedo shader and baked lighting. Colour/emissive factors and double-sidedness follow the supplied asset. Normal maps respect the existing Normal maps switch. Roughness/metalness are not converted into a new PBR lighting system: this engine's alias path is baked-light plus its existing enhanced relighting. `R_CloneAliasMaterial` retains shader callbacks when held weapons and shell instances clone a material. Viewmodel clones are cached per source until map teardown, including classic clones, so changing weapon does not dispose a material while its asynchronous program compilation is pending.

## Fitting and motion

Quake axes are +X forward, +Y left, +Z up. Supplied hierarchy scales and orientations differ. The version-2 rocket correction supersedes the initial mistaken signed mapping; see owner refinements above. The axe's donor alignment includes 35-degree Y rotation for offline UV projection only; the rendered native axe has no added rotation, scale or pose modification.

Each held model and pickup is fitted separately in **native model-local coordinates**. In particular, pickups retain their existing vertical hover offset and entity rotation rather than being centred at ground level. Held firearm MDLs park independent muzzle-flash components behind the camera in their rest frame. Those completely negative-X components are excluded from physical weapon measurements; including them makes the replacement several times too long. The axe's separate 58-vertex arm component is excluded from fitting and retained in rendering.

Most rest fits use `replacement = orientedSource * scale + offset`, measured from the six native body bounding planes. The held grenade uses barrel-ring calibration and the held rocket adds the explicit owner-requested offset, both recorded above. Per-axis calibration is intentional to match requested native dimensions; the source's aspect ratio can change during initial fitting. After that fixed calibration, Kabsch rigid transforms from corresponding native weapon vertices transfer each native pose's rotation and translation. There is no per-frame stretching. Existing animation smoothing linearly blends corresponding imported pose vertices, as it does for native models. This preserves native timing and approximate recoil/swing; authored static meshes cannot reproduce independent animated moving parts exactly.

## Shot and casing lifecycle

`CL_ParseStartSoundPacket` confirms the local player's weapon-channel sounds before audio audibility/mute checks. Independent inspection of bundled `progs.dat` established that `weapons/guncock.wav` is emitted only by `W_FireShotgun`, and `weapons/shotgn2.wav` only by `W_FireSuperShotgun`. Its final-single-shell path calls `W_FireShotgun`, so the sound also establishes the correct fallback count. Muzzle flashes/render frames, active-ammo changes, weapon selection and pickup events do not emit shells. Title demos are excluded from accumulation. This mapping is qualified for the bundled vanilla progs, not arbitrary mods with different sound semantics.

`src/newer/render/r_shells.js` records one or two casings at the receiver/chamber side in weapon-local coordinates and transforms through the most recent actual held pose. A distant/stale held pose falls back to packet-origin plus current aim, preventing emission from a stale position after teleportation. Casings inherit some player velocity, eject sideways/upwards, tumble under native 800-unit gravity, bounce with damping and settle on upward-facing surfaces. Sweeps subdivide at 1/120 s; client-time pauses produce no motion, and long browser stalls clamp catch-up to 0.25 s.

`src/newer/render/r_shelltrace.js` uses the existing BSP recursive hull algorithm with centre and six radius probes. Both world geometry and transformed brush entities (lifts/platforms/doors) can stop casings. Resting casings retain local position/quaternion on their supporting brush, follow its motion, and resume falling if it disappears. Malformed saved support records are discarded safely and gravity resumes. This is cosmetic casing collision, not a new gameplay rigid-body engine; casings do not block players or interact with each other.

Records are per map. Settled world casings are not resimulated; active/supported casings update, and rendering grows in 256-instance chunks without overwriting earlier casings. There is no TTL, ring, oldest-first cleanup or hidden cap. Retention necessarily increases geometry instances and save size during an arbitrarily long session. `R_NewMap` detaches the previous map's instances but keeps its records; returning reattaches them. Explicit new-game/map command resets the collection and disposes instance resources.

`save` appends a brace-free base64 JSON comment (`// quaked-shells-v1 ...`) after the normal version-5 data in the **same localStorage value**. The world and casing snapshot are therefore saved atomically. Native edict parsing ignores the trailing comment; existing saves with no comment restore an empty collection. Loading restores every cached map's casing positions, velocities, orientation and support. Browser reload alone is not autosave: use ordinary Save/Load for durable state.
