What each request needs

generateTile(surfaceConfig, tileX, tileY)

The seed, feature settings, resolution and surface coordinate frame belong to the whole surface. Only the tile coordinates change. Tiles can arrive in any order, including negative coordinates.

The demo uses two worker threads and a 96-page least-recently-used cache. A tile is generated once and sampled on the GPU thereafter. Drag the map to browse other coordinates; click to generate there.

What stays unchanged

The six supplied textures are embedded unchanged at their original resolutions. Wall textures are uwall1_2, bricka2_2 and rock1_2. Ground-only textures are rock4_1, wgrnd1_6 and wgrnd1_5. Selecting an original applies its own saved settings and the correct surface profile. Changing the profile selects a texture from that group; a ground-only image is never used as a wall material.

All three ground presets use feature size 0.30, warp 0.70, fracture 0.00, detail 1.50, 64 intervals and relief amplitude 0.10. The three wall presets are unchanged. Ground uses the gentler height function, not the cliff formations. The height field is independent of the color texture; these presets do not extract texture-aligned depth from the images.

The surface seed, tile coordinates, original image bytes and mesh stay unchanged. Changed shape settings regenerate the same tile region. Color repeats once per tile. Relief mode shifts texture lookup positions; Normals mode leaves them unchanged. All six presets use 64 intervals, 65 shared-edge samples and two real gutter samples on each side (69 × 69 stored samples). Level-zero filtering is shown here; production mip levels need consistent filtering and gutters at every level.

PNG export contains the selected 3 × 3 region with shared edges included only once. White means higher. The image is linear 16-bit data, not a color texture.
